# EchoWitness

An AI-powered platform that lets harassment survivors capture real-time evidence during an incident and turns it into a legally structured, POSH Act–compliant report through a trauma-informed AI interview.

## The problem

Survivors rarely capture evidence in the moment — fear, panic, and the lack of a discreet tool get in the way. When documentation happens later, from memory, it's fragmented and legally weak. Existing evidence-storage apps only store what you give them; none convert it into a structured, legally usable, POSH Act–mapped report.

## How it works

1. **Live Capture** — a one-tap, optionally disguised trigger records audio, live transcription, timestamp, and GPS.
2. **Guided Reconstruction** — an AI-led, trauma-informed interview fills in gaps for survivors who'd rather type than record live.
3. **Automated structuring** — raw voice or text is turned into a neutral, factual, chronological incident record.
4. **Legal mapping** — the entry is matched against the relevant POSH Act section, with a plain-language justification.
5. **Report generation** — one click produces a PDF formatted for HR, an Internal Committee, or the police.
6. **Tamper-evident storage** — every capture is SHA-256 hashed at creation and again at finalization, so the record's integrity can be verified later.

## Tech stack

- **Frontend:** React 19 + TypeScript, Vite, PWA (installable, offline-capable shell)
- **Backend:** Firebase (Auth, Firestore, Storage)
- **AI:** Gemini API — transcription structuring, interview question generation, legal mapping, pattern/escalation detection
- **PDF export:** jsPDF (client-side)
- **Local evidence storage:** IndexedDB (screenshots/PDFs stay on-device, never uploaded)
- **Integrity hashing:** Web Crypto API (SHA-256)

## Getting started

### Prerequisites

- Node.js 18+
- A Firebase project (Auth with Anonymous sign-in enabled, Firestore, Storage)
- A Gemini API key ([Google AI Studio](https://aistudio.google.com))

### Setup

```bash
git clone https://github.com/Karthisha25/EchoWitness.git
cd EchoWitness
npm install
```

Copy the example environment file and fill in your own keys:

```bash
cp .env.example .env
```

```
VITE_FIREBASE_API_KEY=
VITE_FIREBASE_AUTH_DOMAIN=
VITE_FIREBASE_PROJECT_ID=
VITE_FIREBASE_STORAGE_BUCKET=
VITE_FIREBASE_MESSAGING_SENDER_ID=
VITE_FIREBASE_APP_ID=
VITE_FIREBASE_MEASUREMENT_ID=
VITE_GEMINI_API_KEY=
```

### Run locally

```bash
npm run dev
```

### Build for production

```bash
npm run build
```

### Deploy (Firebase Hosting)

```bash
npm run build
firebase deploy --only hosting
```

## Project structure

```
src/
  components/   Shared UI (auth guard, layout, evidence uploader, spinner/states)
  config/       Firebase initialization
  constants/    POSH Act reference text and legal disclaimer
  context/      Auth context/provider
  hooks/        Media recorder, speech recognition, geolocation, incident data
  screens/      One folder per app screen (Home, Live Capture, Guided Interview,
                Entry Review, Legal Mapping, Report Preview, History, Login)
  services/     Firestore reads/writes, Gemini calls, IndexedDB, PDF generation, hashing
  types/        Shared TypeScript types for the Incident data model
functions/      Firebase Cloud Functions (currently a stub — see note below)
```

## Known limitation

The project spec calls for all Gemini API calls to run through Firebase Cloud Functions, so the API key never reaches the browser. That backend piece (`functions/src/index.ts`) is currently just a stub — Gemini is called directly from the client for now, with the key exposed via `VITE_GEMINI_API_KEY`. This is fine for local development and demos, but before any wider or production use, that logic should move server-side.
